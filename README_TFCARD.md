# 小智 AI · TF 卡扩展功能（立创实战派 ESP32-S3）

在 [xiaozhi-esp32](https://github.com/78/xiaozhi-esp32) 的基础上，为**立创实战派 ESP32-S3 开发板**
（2.0 寸 320×240 触摸屏）增加了一整套依赖 TF 卡的本机功能：音乐播放、相册、电子书、网络收音机、
语音备忘、日志黑匣子，并让语音助手可以听懂「打开某某」来直接切到对应界面。

---

## ⚠️ 测试范围（务必先看）

**本项目仅在以下硬件上实测通过：**

| 项目 | 型号 |
|---|---|
| 开发板 | 立创实战派 ESP32-S3（LCKFB SZPI-ESP32S3） |
| 主控 | ESP32-S3 N16R8（16MB Flash / 8MB PSRAM） |
| 屏幕 | 2.0 寸 ST7789，320×240，SPI |
| 触摸 | FT6336 电容触摸（I2C） |
| 音频 | ES8311（输出）+ ES7210（输入） |
| TF 卡 | SDMMC 1 线模式（CLK=GPIO47 / CMD=GPIO48 / D0=GPIO21） |

- **其他板子未经验证**，引脚、屏幕方向、编解码器、SD 卡接线都不同，直接烧进去大概率不能跑。
- 上游支持的几百种板子在 `main/boards/` 下，本项目的改动**只动了 `boards/lckfb/szpi-esp32s3/`**，
  其余板子理论上不受影响，但也没测过。
- 屏幕坐标系为 **LVGL 逻辑画布 320×240（横屏）**，物理屏靠 `SWAP_XY` 旋转成 240×320。
  改 UI 时务必按 320×240 排布，否则元素会跑到屏幕外。

## 功能与使用方法

所有功能的数据都放在 TF 卡上，**拔卡拷文件、插回板子即可生效**，不需要重新烧录固件。

TF 卡目录结构：

```
/sdcard/
├── music/          音乐
│   ├── 01.mp3 …
│   └── playlist.txt
├── photos/         相册（只认 .jpg / .jpeg）
├── books/          电子书（.txt / .md）
├── notes/          语音备忘（程序自动写）
├── record/         录音文件（.wav）
├── radio/
│   └── radio.txt   电台列表
├── log/            日志黑匣子（程序自动写）
└── assets/emoji/   卡上表情包（可选，放不放都能跑）
```

> 卡必须格式化为 **FAT32**。
> 固件已关闭「挂载失败自动格式化」——插一张 exFAT 卡不会把卡格式掉，只是挂载失败、退回无卡模式。

### 1. 音乐播放器

**导入方式**

1. 把 MP3 文件拷进 `/sdcard/music/`
2. 在同目录建 `playlist.txt`，一行一首，格式为 `文件名|显示名`：

```
01.mp3|周杰伦 - 晴天
02.mp3|李宗盛 - 山丘
```

- 不写 `playlist.txt` 也能播，此时直接显示文件名。
- 显示名支持中文（文件需为 UTF-8 编码）。
- 目前只认 **MP3**（44.1kHz / 48kHz，单声道或立体声都行）。

**界面操作**

- 触摸菜单「音乐」进入播放界面
- 左上角「首页」回对话界面、「列表」进歌曲列表
- 播放界面：「上一首 / 暂停（继续） / 下一首」、音量加减（中间显示当前音量值）、循环模式（列表循环 / 单曲循环 / 随机）
- 歌曲列表：一屏约 6 行、上下滑动、点某行直接播那首、正在播的那首会高亮

---

### 2. 相册（电子相册）

**导入方式**

1. 把照片拷进 `/sdcard/photos/`
2. 支持 **jpg / jpeg（大小写都行）**

**格式与大小限制（重要）**

| 项目 | 限制 |
|---|---|
| 格式 | **仅 JPEG**（png、heic、webp 都不认） |
| 单张大小 | **≤ 1.2MB**（超过会被跳过） |
| 建议分辨率 | 长边 ≤ 2000px。太大了能显示但解码慢、占内存 |
| 总量建议 | 一两百张以内，太多翻页会变慢 |

- 缩略图按自然序排列（`2.jpg` 排在 `10.jpg` 前面，和 Windows 一致）
- 解不出来的图会在格子上标注「打不开 + 文件名」，不会静默消失
- 语音「打开相册」也可以进（需先配好语音工具，见第 7 节）

**界面操作**

- 2×2 网格预览 → 点某张进全屏 → 全屏左右滑动翻页、中间点一下退出全屏
- 首页有「幻灯片」按钮：自动随机播放，每张停 15 秒
- 进入相册后**不会自动息屏**

> 因为 JPEG 解码需要一大块**连续内存**，本项目特意在打开相册前释放收音机的常驻缓冲。
> 如果你自己在这个基础上加别的功能，注意别把 PSRAM 占成碎片，否则会出现「缩略图有的显示有的空白」。

---

### 3. 电子书阅读器

**导入方式**

1. 文本文件放 `/sdcard/books/`
2. 支持 **.txt / .md**
3. 编码：**UTF-8 和 GBK 都自动识别**（GBK 内置 21791 字码表转换）

**界面操作**

- 进「电子书」先看到两个目录：`books`（你放的书）和 `notes`（小瑞帮你记的备忘）
- 点书进入正文，底部三个按钮：**上一页 / 返回 / 下一页**
- 阅读进度会记住，下次打开接着看

---

### 4. 网络收音机

**导入方式**

编辑 `/sdcard/radio/radio.txt`，一行一个台，格式 `名称|URL`，`#` 开头为注释：

```
01 中国之声|http://ngcdn002.cnr.cn/live/zgzs/index.m3u8
02 经济之声|http://ngcdn002.cnr.cn/live/jjzs/index.m3u8
10 兰州综合广播|https://liveplus.lzr.com.cn/aac_zhgb/HD/live.m3u8
```

**支持的流类型**

| 类型 | 说明 | 例子 |
|---|---|---|
| HLS（m3u8 + TS 封装） | 分片是标准 TS，内部 AAC 音频 | CNR 各台、甘肃各台 |
| HLS（m3u8 + 裸 ADTS） | 分片直接是 `.aac`，可能带 ID3 头 | 兰州各台 |
| MP3 直连 | 直接给 mp3 URL | 部分网络台 |

- **加密流（`#EXT-X-KEY`）不支持**
- 固件内置了一份电台列表作为兜底，进收音机点「重置」会把它写进卡里覆盖现有列表
- 想加台改卡上的 `radio.txt` 就行，**进界面自动重读**，不用重启
- 拔卡改完再插回：进一次收音机会自动重新挂载，不需要按 R 键复位

**界面操作**

- 列表页：上下滑动选台、点一台开始播
- 播放页：左上角「首页 / 列表」，中间台名和状态，音量加减（中间显示当前音量），底部「上一台 / 停止 / 下一台」
- 内置**分片预取**和**列表提前刷新**，专门治分片短（3~4 秒）的台周期性卡顿

---

### 5. 语音备忘 & 录音

- 菜单「录音」：开始录音到 `/sdcard/record/*.wav`，单次最长 5 分钟
- 菜单「记录」：进入记录模式后，对小瑞说的话会被写成 Markdown 存到 `/sdcard/notes/YYYY-MM-DD.md`
- 备忘可以通过「电子书 → notes」在设备上直接翻看

---

### 6. 日志黑匣子

- 所有 ESP_LOG 输出会同时写进 `/sdcard/log/log0.txt`
- 单文件上限 256KB，写满自动轮转；内存里是 16KB 环形缓冲
- 出现崩溃、重启、异常时可以事后拔卡查日志，不用一直挂着串口

---

### 7. 语音控制打开功能（MCP 工具）

固件里注册了以下 MCP 工具，让对话模型可以直接调用：

| 工具名 | 作用 |
|---|---|
| `self.app.open_music` | 打开音乐播放器 |
| `self.app.open_photos` | 打开相册 |
| `self.app.open_books` | 打开电子书 |
| `self.app.open_radio` | 打开网络收音机 |
| `self.app.back_home` | 关闭当前功能回到对话界面 |

**启用方法**

1. 工具注册在固件里，烧录后自动生效
2. 服务端（例如官方 xiaozhi.me 后台）的对话模型需要能看到设备上报的工具列表 ——
   官方服务端支持设备 MCP 工具，无需额外配置
3. 之后直接说「打开收音机」「打开相册」即可

**建议在人设里加一句**：调用这些工具时不要说话、直接执行。
否则模型会先回一句「好嘞，收音机打开啦」，那句话的语音会和电台声抢喇叭（固件已做打断，但会切掉半句）。

**实现要点（改代码时注意）**

- MCP 回调跑在**协议线程**，绝对不能直接操作 LVGL 或音频服务
- 用 `lv_async_call` 投递到 LVGL 任务（那时已持 LVGL 锁）；用 `Application::Schedule` 会因无锁而崩溃
- 界面是懒创建的，语音路径可能没走过 `InitializeTouch()` 的创建，回调里要先 `Create()`
- 打开后调 `SetDeviceState(kDeviceStateIdle)` 结束对话，否则她继续聆听，后续指令会串到别的界面

## 预编译固件（不想自己编就用这个）

仓库里放了一份编好的应用固件，刷进去即可，不必搭 ESP-IDF 环境。

| 项目 | 值 |
|---|---|
| 文件 | `firmware/xiaozhi-lichuang-s3-20261118.bin` |
| 大小 | 3682192 字节 |
| SHA256 | `357b70eeaf61923b1035645772624fac03bcb470a8433c5c03b6484e2d1cffee` |
| 对应源码提交 | `c3a18a7d` |
| 适用板型 | 立创实战派 ESP32-S3（**仅此板验证过**） |

**只写 app 分区，别动其它分区：**

```bash
esptool.py --chip esp32s3 -p /dev/ttyACM0 --baud 460800 \
  write_flash 0x20000 xiaozhi-lichuang-s3-20261118.bin
```

⚠️ **不要** `write_flash 0x0`、不要 `erase_flash`、也不要直接用 `idf.py flash` 做全量烧录。
分区表（`0x8000`）和资源分区 `assets`（`0x800000`，8 MB，装表情、中文字库、唤醒词模型）
一旦被覆盖，轻则表情和字库全丢，重则开机起不来 —— assets 得回上游工程用
`scripts/spiffs_assets/build.py` 重新生成，很麻烦。

**这个固件里不含任何账号信息**：只有应用代码。WiFi 凭据、API key、bot token 都在
NVS 分区里，不在这个文件中，所以可以放心分发给别人。

## 编译方法

```bash
# ESP-IDF v6.0.x
idf.py set-target esp32s3
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

- 应用分区剩余约 11%，空间不宽裕，加功能前先看 `xiaozhi.bin binary size` 那行
- 如果从本仓库首次编译，`sdkconfig` 会被 sdkconfig.defaults 重新生成

## 已知限制

- **仅立创实战派 ESP32-S3 验证过**，其他板子需要自己适配引脚和屏幕
- 相册只认 JPEG、单张 ≤1.2MB
- 收音机不支持加密 HLS 流
- 播放队列深度（`MAX_PLAYBACK_TASKS_IN_QUEUE`）从上游的 2 调到了 8，用于抗抖动；
  极端情况下语音应答会慢约 170ms
- 语音反馈文本由服务端生成，固件只能在功能界面期间定时清屏
